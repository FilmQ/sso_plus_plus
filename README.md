# SSO Plus Plus: SST Injury Claim & Treatment Application

ระบบยื่นคำร้องและนัดหมายการรักษากรณีประสบอันตราย, ศูนย์ฟื้นฟูผู้ป่วย สำนักงานประกันสังคม.

The code follows the SA report. Read `docs/CLAUDE_CODE_BRIEF.md` and `docs/spec/README.md` first.
Decisions and deviations from the report are in `docs/DECISIONS.md`.

## Parts

| Folder | Content |
|---|---|
| `lib/` | Flutter app (Material 3, web and mobile). `lib/main.dart` is the user app. `lib/main_console.dart` is the officer and consultant console. |
| `server/` | Dart API server: Controller, Model, Repository and `DBConnector` (SA report 2.18). |
| `server/lib/repository/sql/` | The 56 SQL statements of `docs/spec/database/queries.sql`, generated by `server/tool/gen_sql.py`. Do not edit by hand. |
| `server/db/` | Infrastructure migrations and seeds that are not in the report. |
| `docs/spec/` | The specification extract of the report. Read-only. |

## What you need

- Flutter 3.47 or later (it includes Dart 3.13).
- Docker Desktop (for PostgreSQL 16).
- `make` (macOS and Linux have it).

## First run

```sh
make db-up          # start PostgreSQL 16 on port 5432
make db-reset       # load docs/spec/database/schema.sql and seed.sql into the dev database
make server         # start the API server on http://localhost:8080
make app            # in a second terminal: the user app in Chrome
make console        # or: the officer and consultant console in Chrome
```

To use a phone emulator, run Flutter with the server address of the host computer, for example
`flutter run -t lib/main.dart --dart-define=API_BASE_URL=http://10.0.2.2:8080` on the Android emulator.

The environment variables of the server are in `.env.example`. The default values agree with
`docker-compose.yml`, so you do not need to set them for development.

## Lint and test

```sh
make lint           # dart analyze (server) and flutter analyze (app)
make test-server    # server tests; they need `make db-up` and they load the test database again
make test-app       # Flutter widget tests
make test           # both
```

The server tests use the database `sst_test`. Each test file loads it again from `schema.sql` and `seed.sql`,
and each test runs in a transaction that rolls back.

## Reset the database

`make db-reset` deletes all data in the dev database and loads the schema and the seed again.
`docker compose down -v` deletes the Docker volume. The next `make db-up` makes a new, empty server.
