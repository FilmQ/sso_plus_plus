# SSO Plus Plus: SST Injury Claim & Treatment Application

ระบบยื่นคำร้องและนัดหมายการรักษากรณีประสบอันตราย, ศูนย์ฟื้นฟูผู้ป่วย สำนักงานประกันสังคม.

The code follows the SA report. Read `docs/CLAUDE_CODE_BRIEF.md` and `docs/spec/README.md` first.
Decisions and deviations from the report are in `docs/DECISIONS.md`.

## Parts

| Folder | Content |
|---|---|
| `lib/` | Flutter app (Material 3, web and mobile). `lib/main.dart` is the user app. `lib/main_console.dart` is the officer and consultant console. |
| `server/` | Dart API server: Controller, Model, Repository and `DBConnector` (SA report 2.18). |
| `server/lib/repository/sql/` | The SQL statements of `docs/spec/database/queries.sql`, generated by `server/tool/gen_sql.py`. Do not edit by hand. |
| `server/db/` | Infrastructure migrations and seeds that are not in the report. `seeds/002_thai_seed_text.sql` changes the typed text and the employer names of `seed.sql` to Thai (D-068). `demo-seeds/` has the extra demo rows (D-066) and moves the seed dates near the load day (D-069). |
| `docs/spec/` | The specification extract of the report. Read-only. |
| `lib/legacy/` | The September draft code, kept until the officer and consultant slices replace it (`docs/DECISIONS.md`, D-012). |

## What you need

- Flutter 3.47 or later (it includes Dart 3.13).
- Docker Desktop (for PostgreSQL 16).
- `make` (macOS and Linux have it).

## First run

```sh
make db-up          # start PostgreSQL 16 on port 5432
make db-reset       # load docs/spec/database/schema.sql and seed.sql into the dev database
make server         # start the API server on http://localhost:8080
make app            # in a second terminal: the user app in Chrome
make console        # or: the officer and consultant console in Chrome
```

To use a phone emulator, run Flutter with the server address of the host computer, for example
`flutter run -t lib/main.dart --dart-define=API_BASE_URL=http://10.0.2.2:8080` on the Android emulator.

The environment variables of the server are in `.env.example`. The default values agree with
`docker-compose.yml`, so you do not need to set them for development.

## Demo guide

This guide shows the full process: claim, verification, appointment, report and treatment. You need the user app and
the console. Do the parts in order. The passwords and the other accounts are in [Seed accounts](#seed-accounts).

### 1. Seed the data and start the application

Seed the data **on the day of the demo**. The seed calculates the appointment and treatment dates from the day that
you load it, so old data can show no future appointments. `make db-demo` also moves the fixed dates of `seed.sql` by
whole weeks, so the last seed day is the last Monday on or before the load day (D-069).

> **Caution:** `make db-demo` deletes all data in the dev database.

Start Docker Desktop, then load the data:

```sh
make db-up          # start PostgreSQL 16
make db-demo        # load the schema, the seed, 86 extra demo claims and the demo files
```

The output must show `Loaded 5 files`, `Loaded 2 demo data files` and `Copied 7 demo files`.
[Demo data](#demo-data) lists the extra claims. For the tests in `SPEC-TEST-PROCESS.md`, use `make db-reset`, because
those tests expect only the seed rows.

Start each part in its own terminal:

```sh
make server         # terminal 1: the API server on http://localhost:8080
make console        # terminal 2: the officer and consultant console in Chrome
```

Each application starts in English. The demo steps use the English labels. To show the Thai labels, choose **ไทย** on
the language toggle (**EN | ไทย**). The toggle is on the Register, Login and Profile pages of the user app, and in the
navigation of the console. Each window keeps its own choice (D-067).

To show the user app on the Android emulator, use this command for terminal 2 and copy the demo files to the emulator:

```sh
flutter run -t lib/main.dart --dart-define=API_BASE_URL=http://10.0.2.2:8080
adb push server/db/demo-files/claims/161/. /sdcard/Download/
```

### 4. Reset the demo

1. Sign out of the user app and the console.
2. Stop the server (Ctrl+C in terminal 1).
3. Run `make db-demo`. The new user and all changes go away, and the dates start from today.
4. Run `make server`.

### 5. Solve problems

| Problem | Solution |
|---|---|
| `failed to connect to the docker API` | Start Docker Desktop, then run `make db-up` again. |
| `make db-up` cannot use port 5432 | Stop the other service that uses port 5432. |
| A list has no appointments or treatments | The data is old. [Reset the demo](#4-reset-the-demo). |
| The app cannot connect to the server | Make sure that `make server` runs. On the Android emulator, use `http://10.0.2.2:8080`. |
| A date or time is incorrect | Set the computer and the emulator to Asia/Bangkok. |
| The labels are in Thai | Choose **EN** on the language toggle. |

## Lint and test

```sh
make lint           # dart analyze (server) and flutter analyze (app)
make test-server    # server tests; they need `make db-up` and they load the test database again
make test-app       # Flutter widget tests
make test           # both
```

The server tests use the database `sst_test`. Each test file loads it again from `schema.sql` and `seed.sql`,
and each test runs in a transaction that rolls back.

## Reset the database

`make db-reset` deletes all data in the dev database and loads the schema and the seed again.
`make db-demo` does the same and also loads the [demo data](#demo-data).
`docker compose down -v` deletes the Docker volume. The next `make db-up` makes a new, empty server.
